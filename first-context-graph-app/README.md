## Quick Start

This project uses **Neo4j Agent Memory Service (NAMS)** — a hosted memory backend. Your `.env` file already contains your API key; the agent reads from and writes to NAMS as you chat with it.

```bash
# Install dependencies
make install

# Edit .env to set ANTHROPIC_API_KEY (required by Strands)
# Then start the application
make start
```

> The graph starts **empty**. Talk to the agent in the chat UI and it will populate memory through use. Want a pre-populated demo with relationships and properties? Re-run the CLI with `--self-hosted --demo`.

- **Backend:** http://localhost:8000
- **Frontend:** http://localhost:3000
- **NAMS Dashboard:** https://memory.neo4jlabs.com

## Memory backend: NAMS

Your project is wired to the hosted Neo4j Agent Memory Service. Memory state lives in the cloud and is shared across processes (web app and `make mcp-server` both read/write the same graph).

**Known limitations on the NAMS API (v0.4):**

| Limitation | Effect | Workaround |
|---|---|---|
| **Relationships** between domain entities are not exposed by NAMS REST as native edges. | The graph view does show edges, because outbound relationships are encoded into the source entity's `description` as a fenced ` ```ccg-edges ` YAML block (see [How NAMS stores relationships](https://github.com/neo4j-labs/create-context-graph/blob/main/docs/docs/explanation/ccg-edges.md)). The frontend parses these blocks to render edges. | Re-scaffold with `--self-hosted --demo` if you need native Cypher edges (e.g. for GDS algorithms or arbitrary path queries). Or wait for NAMS `add_relationship` — when it lands, a one-shot migration replays the `ccg-edges` blocks as native edges. |
| **Entity properties** beyond `name` / `type` / `description` are dropped by the REST API. | Demo properties are flattened into the `description` field as a markdown block. | Read the description field; structured property access lands when NAMS exposes the full write API. |
| **Preferences and facts** are not exposed by NAMS REST. | `auto_preferences` is forced off; the SSE `preferences_detected` event will be empty. | Use the self-hosted bolt backend if you need preference/fact tracking. |
| **GDS** (Graph Data Science) endpoints `/gds/communities` and `/gds/pagerank` return `501 Not Implemented`. | Community detection and PageRank are unavailable. | Self-hosted Neo4j with the GDS plugin enabled. |
| **Ad-hoc Cypher** via `POST /cypher` returns `503`. | The cypher console / "Run Cypher" actions are disabled. | Connect Neo4j Browser to a self-hosted instance for arbitrary Cypher. |
| **Schema introspection** via `GET /schema` is not exposed — the response is synthesized from your ontology's entity types. | The schema visualization works but doesn't reflect server-side schema changes. | The synthesized view tracks `data/ontology.yaml`; edit there if you need to change it. |
| **MCP server** is forced to the `core` profile (6 tools), because the extended tool set relies on preference/fact APIs that NAMS doesn't yet expose. | `make mcp-server` exposes 6 tools instead of 16. | Self-hosted bolt backend supports the full `extended` profile. |

For the full relationship-rich demo experience, re-scaffold with `--self-hosted`.

### Diagnosing NAMS connection failures

`GET /health` reports a categorized error when NAMS init fails:

```json
{
  "status": "degraded",
  "memory_backend": "nams",
  "nams": false,
  "nams_error": "auth",
  "nams_error_message": "NAMS authentication failed — verify MEMORY_API_KEY at https://memory.neo4jlabs.com (key may be invalid or expired).",
  "nams_error_detail": "HTTP 403",
  "nams_dashboard": "https://memory.neo4jlabs.com"
}
```

Categories: `auth` (401/403), `rate_limit` (429), `network` (5xx/timeout/DNS), `config` (missing key / endpoint), `unknown`.

## Switching memory provider/model

The memory layer accepts [LiteLLM-style](https://docs.litellm.ai/) provider strings via env vars:

```bash
# In .env
MEMORY_LLM=anthropic/claude-haiku-4-5
MEMORY_EMBEDDING=sentence-transformers/all-MiniLM-L6-v2
```

Native adapters are resolved first (Anthropic, OpenAI, Bedrock, Vertex AI, SentenceTransformers). Everything else (Ollama, Groq, Together, Mistral, …) routes through LiteLLM.

## Agent Tools

The AI agent has access to the following domain-specific tools:

- **search_customer** — Search for clients, advisors, or other people by name or role
- **get_customer_decisions** — Get all decisions related to a specific client
- **find_similar_decisions** — Find decisions similar to a given decision using vector similarity
- **get_causal_chain** — Trace the causal chain of events from a decision
- **detect_fraud_patterns** — Detect unusual transaction patterns that may indicate fraud
- **list_accounts** — List Account records with optional limit
- **get_account_by_id** — Get a specific Account by ID with all connections
- **execute_cypher** — Run ad-hoc Cypher queries
- **get_schema** — View the graph schema

## Agent Framework: Strands

This project uses [Strands Agents](https://github.com/strands-agents/strands-agents) with `@tool` decorators and an Anthropic-backed model. Requires `ANTHROPIC_API_KEY` in your `.env` file. Runs synchronously via `asyncio.to_thread()`.

Streaming is limited to real-time tool call visualization; text arrives after the agent completes.

See `backend/app/agent.py` for the full implementation.

| `BACKEND_PORT` | Backend port (default: 8000) |
| `FRONTEND_PORT` | Frontend port (default: 3000) |

## Troubleshooting

### Neo4j Connection Errors

**"Neo4j is unavailable" on all endpoints**
- Verify your `.env` file has correct `NEO4J_URI`, `NEO4J_USERNAME`, and `NEO4J_PASSWORD`
- Run `make test-connection` to validate credentials

**`/health` shows `"status": "degraded"` with a `memory_error` while chat still works**
- The Neo4j connection is fine but memory writes are failing — most often the
  database name: if your instance's database isn't literally named `neo4j`
  (common on Aura instances provisioned via the Aura API/CLI), set
  `NEO4J_DATABASE` in `.env` and restart
- `memory_error` is the classified category (`auth`/`rate_limit`/`network`/`config`/`unknown`);
  `memory_error_detail` carries the short technical detail

**Extra variables in `.env`**
- The backend accepts extra environment variables, so standard Neo4j Aura `.env` exports (with `NEO4J_DATABASE`, `AURA_INSTANCEID`, etc.) work without editing

### Backend Issues

**Port already in use**
- Change `BACKEND_PORT` in `.env` (default: 8000)
- Kill existing process: `lsof -ti:8000 | xargs kill`

**API key not set**
- Set `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` in `.env` depending on your agent framework

### Frontend Issues

**Build errors after `npm install`**
- Delete `node_modules` and `package-lock.json`, then run `npm install` again
- Ensure Node.js 18+ is installed
