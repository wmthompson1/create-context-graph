# Plan 004 Tasks: Round-Trip Ontology Regeneration

## Guardrails

- [ ] Confirm `ontology.snapshot.json` was generated by Plan 003 for
	`salt.manufacturing.v1.0`.
- [ ] Confirm the manifest keeps the canonical v1.0 ID and IRI; treat `v1.0-R1`
	only as a regeneration-run label.
- [ ] Define a supported source-policy allowlist that rejects SAP source data,
	CDS content, transactional data, external JDBC endpoints, and schema
	inference.
- [ ] Keep GitHub Copilot and librarian MCP access read-only; add no graph
	mutation tools.

## Regeneration Module

- [ ] Add reusable snapshot and manifest loading/validation functions to the
	ontology tooling module.
- [ ] Validate matching ontology ID, IRI, version, namespace, and source-policy
	values before generating or writing an artifact.
- [ ] Validate every class/property IRI belongs to the canonical ontology
	namespace and every property kind is `object` or `datatype`.
- [ ] Sort classes, properties, domains, ranges, and artifacts by stable IRI or
	path before rendering.
- [ ] Establish fixed UTF-8, LF, indentation, and trailing-newline rendering
	rules for byte-stable output.
- [ ] Render artifacts in memory and calculate their SHA-256 values before any
	file write.
- [ ] Write artifacts atomically to the manifest's canonical output directory.

## Artifact Renderers

- [ ] Implement JSON-to-Turtle generation for the ontology header, classes,
	object/datatype properties, labels, domains, and ranges.
- [ ] Implement JSON-to-OBDA generation using only synthetic in-memory H2
	class, scalar-property, and relationship mappings.
- [ ] Implement deterministic smoke, lineage, provenance, and semantics SPARQL
	query generation from snapshot/manifest metadata.
- [ ] Regenerate `ontop.properties` with the approved in-memory H2 datasource.
- [ ] Emit `regeneration-report.json` containing ontology ID, snapshot hash,
	artifact hashes, validation outcomes, and regeneration-run ID without
	credentials or source data.

## CLI and Local Validation

- [ ] Add `scripts/regenerate_artifacts.py` accepting `--snapshot`,
	`--manifest`, `--output-dir`, Neo4j connection options, and a no-write
	dry-run mode.
- [ ] Reuse the existing `.env` Neo4j host/port/user/password resolution and
	keep command-line values higher priority.
- [ ] Parse the regenerated Turtle with RDFLib before Neo4j provenance writes.
- [ ] Run `ontop.ps1 validate` against the regenerated artifacts before Neo4j
	provenance writes.
- [ ] Run every generated/registered smoke and acceptance SPARQL query through
	Ontop before Neo4j provenance writes.
- [ ] Stop before the Neo4j write phase when any local validation fails and
	preserve the failure in the regeneration report.

## Neo4j Provenance

- [ ] Create an `IngestionRun` with `run_type = 'regeneration'`, snapshot hash,
	and `status = 'started'` only after local validation succeeds.
- [ ] Upsert the regenerated artifact checksums using only the selected
	`ontology_id` scope.
- [ ] Link each artifact to the regeneration run with `[:USED_ARTIFACT]` and
	link the run to the ontology with `[:INGESTED]`.
- [ ] Set the successful run status to `regenerated`; record a bounded error
	summary and `failed` status on write failure.
- [ ] Verify the provenance implementation does not create or modify ontology,
	class, property, knowledge-base, policy, domain, or range records.

## Tests and Acceptance

- [ ] Add unit tests for snapshot/manifest compatibility, ordering, stable
	hashes, and byte-for-byte deterministic output.
- [ ] Add rejection tests for unsupported property kinds, foreign IRIs, and
	SAP/CDS/table references.
- [ ] Add RDFLib assertions for regenerated classes, property kinds, and
	domain/range statements.
- [ ] Add Ontop integration coverage for the OBDA/properties pair and all
	generated SPARQL queries.
- [ ] Add mocked Neo4j tests for provenance ordering, relationship creation,
	and failure handling.
- [ ] Run regeneration twice against unchanged inputs; assert identical artifact
	bytes and hashes, unchanged ontology metadata, and exactly one additional
	successful regeneration run per invocation.
- [ ] Record the command outputs and final artifact/run counts in the Plan 004
	completion note.
