# **📘 Plan 004 — Round‑Trip Ontology Regeneration (v1.0 → v1.0‑R1)**  
**Purpose:**  
Regenerate all ontology artifacts (`.ttl`, `.obda`, `.sparql`, `ontop.properties`) **from the Neo4j snapshot**, not from the original Turtle, ensuring the ontology is fully reversible and provenance‑complete.

**Scope:**  
Metadata‑only.  
No SAP source data.  
No transactional content.  
No CDS extraction.  
No schema mutation beyond ontology metadata.

---

## **1. Inputs**
- `ontology.snapshot.json` (generated by Plan 003)
- `manifest.json` (canonical v1.0)
- Neo4j metadata (classes, properties, domain/range evidence, artifacts, ingestion runs)
- SALT manufacturing ontology v1.0 IRI + identifier

---

## **2. Outputs**
Regenerated, deterministic artifacts:

```
salt-manufacturing.ttl
salt-manufacturing.obda
salt-manufacturing.sparql
ontop.properties
```

Plus updated provenance:

```
OntologyArtifact nodes (checksummed)
IngestionRun (status=regenerated)
```

All written under:

```
my-mrp-kb/ontology/salt/manufacturing/v1.0/
```

---

## **3. Requirements**
### **3.1 Determinism**
Regeneration must be **byte‑for‑byte reproducible**:

- same snapshot → same artifacts  
- same manifest → same artifacts  
- same ontology_id → same IRIs  

### **3.2 Provenance**
Every regenerated artifact must:

- be hashed  
- be linked to a new `IngestionRun`  
- include version + ontology_id  
- include snapshot hash  

### **3.3 Safety**
- No SAP data  
- No CDS content  
- No transactional tables  
- No external schema inference  
- Metadata only

### **3.4 Validation**
Regenerated artifacts must pass:

- Ontop validation  
- Turtle parse (RDFLib)  
- OBDA parse (Ontop)  
- SPARQL parse (Ontop)  
- Neo4j provenance checks  

---

## **4. Tasks**

### **Task 4.1 — Implement `regenerate_artifacts.py`**
A new CLI:

```
scripts/regenerate_artifacts.py \
    --snapshot ontology.snapshot.json \
    --manifest manifest.json \
    --output-dir my-mrp-kb/ontology/salt/manufacturing/v1.0/
```

Responsibilities:

- load snapshot  
- load manifest  
- regenerate `.ttl`, `.obda`, `.sparql`, `ontop.properties`  
- write artifacts  
- compute SHA‑256 hashes  
- produce a regeneration report  

---

### **Task 4.2 — JSON → Turtle generation**
Mapping rules:

- `classes[]` → `owl:Class`  
- `properties[]` → `owl:ObjectProperty` or `owl:DatatypeProperty`  
- `domains[]` → `rdfs:domain`  
- `ranges[]` → `rdfs:range`  
- ontology_id → base IRI  
- version → ontology header  

Output: `salt-manufacturing.ttl`

---

### **Task 4.3 — JSON → OBDA generation**
Mapping rules:

- each class → synthetic H2 table  
- each property → synthetic column  
- each relationship → synthetic join table  
- ontology_id → mapping prefix  
- version → mapping header  

Output: `salt-manufacturing.obda`

---

### **Task 4.4 — JSON → SPARQL acceptance queries**
Generate:

- `salt-manufacturing.sparql`  
- `acceptance/lineage.sparql`  
- `acceptance/provenance.sparql`  
- `acceptance/semantics.sparql`  

Queries must validate:

- class existence  
- property existence  
- domain/range correctness  
- artifact count  
- ingestion run count  
- ontology IRI correctness  
- version correctness  

---

### **Task 4.5 — JSON → Ontop properties**
Regenerate:

```
jdbc.url=jdbc:h2:mem:kb
jdbc.driver=org.h2.Driver
```

Output: `ontop.properties`

---

### **Task 4.6 — Ontop validation**
Run:

```
ontop.ps1 validate
```

Must succeed before provenance write.

---

### **Task 4.7 — Provenance update**
Create:

- new `IngestionRun` (type=`regeneration`)  
- new `OntologyArtifact` nodes  
- link artifacts → run → ontology  

No class/property/relationship writes.

---

### **Task 4.8 — Idempotence test**
Run regeneration twice:

- artifacts identical  
- hashes identical  
- run count increments  
- ontology metadata unchanged  

---

## **5. Deliverables**
- `regenerate_artifacts.py`  
- regenerated artifacts  
- updated provenance  
- validation logs  
- idempotence report  
- Plan 004 completion note  

---

## **6. Success Criteria**
- Ontology artifacts regenerate deterministically  
- Ontop validation passes  
- Neo4j provenance updated  
- No SAP data touched  
- No schema mutation  
- Snapshot → artifacts → snapshot round‑trip is reversible
