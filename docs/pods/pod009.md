# ⭐ Step-by-Step Walkthrough with Direct Comparison

This is a baseline-vs-manufacturing walkthrough. At each stage, we compare the generic tutorial domain (`financial-cost-management`) against the manufacturing scaffold (`v1.1`) so the distinction is explicit and easy to reason about.

---

### **Tutorial Domain: financial-cost-management**
### **Comparison Domain: manufacturing (v1.1)**

---

## **Step 1 — Render the baseline tutorial app**

### What the agent should do
Render a new project using:

- **domain:** `financial-cost-management`  
- **framework:** `strands`  
- **neo4j_type:** `existing`  
- **output folder:** `first-context-graph-app` (or a temp directory)

### What you should look for
The tutorial scaffold will contain:

```
first-context-graph-app/
  context-graph/
    financial-cost-management/
      domain.yaml
      tools/
        financial-cost-management-tools.yaml
      (usually no reasoning/strategies.yaml)
  backend/
    app/
      agent.py
      financial_cost_management_reasoning.py
    pyproject.toml
```

### How this compares to manufacturing
Your manufacturing scaffold contains **three catalogs**:

- `domain.yaml`
- `manufacturing-tools.yaml`
- `reasoning/strategies.yaml`  ← **not present in tutorial domains**

And your backend includes:

- `manufacturing_reasoning.py` with **bounded Cypher strategies**
- startup validation of:
  - ontology identity  
  - tool catalog  
  - reasoning catalog  
  - read‑only Cypher  
  - max hop constraints  

The tutorial scaffold is intentionally much simpler.

---

## **Step 2 — Compare the two scaffolds**

Use this checklist:

### **Context‑graph package**
- **Tutorial:**  
  - small domain  
  - minimal tools  
  - no reasoning strategies  
- **Manufacturing:**  
  - full v1.1 ontology mapping  
  - six catalog‑backed tools  
  - bounded Cypher‑only reasoning strategies  
  - no GDS artifacts  

### **Startup behavior**
- **Tutorial:**  
  - loads domain + tools  
  - basic agent startup  
- **Manufacturing:**  
  - validates all three catalogs  
  - enforces `$ontology_id = salt.manufacturing.v1.1`  
  - enforces read‑only Cypher  
  - enforces max 4 hops  
  - rejects missing or malformed catalogs  

### **Agent module**
- **Tutorial:**  
  - simple agent with 1–2 tools  
- **Manufacturing:**  
  - six tools  
  - evidence‑prompt contract  
  - SSE tool‑event citations  
  - explicit evidence paths  

### **Reasoning layer**
- **Tutorial:**  
  - usually none beyond basic graph access  
- **Manufacturing:**  
  - BOM requirements  
  - schedule contention  
  - supplier coverage  
  - production lineage  

This comparison is the heart of Step 2.

## **Step 4 — Manufacturing Backend (v1.1)**  
### Paste this directly into your agent:


This demonstrates the **strict superset** nature of the manufacturing scaffold and proves the difference from the baseline tutorial domain.
